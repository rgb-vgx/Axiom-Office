## What's in it

12 sheets, 50,500 raw SKU-location records (50,000 distinct + 500 duplicates), 12 months of history, **2,156,652 live formulas** across 6.6M cells.

Raw data is deliberately dirty: 500 duplicate rows, 6,082 records with missing values, 388 bogus text tokens in numeric fields, negative stock/cost/lead-time, zero-demand SKUs, extreme-demand SKUs, and 7,082 long-lead-time records. `Raw_SKU_Data` keeps it untouched and flags every row; the calculation sheets run on the cleaned/de-duplicated equivalent.

**One lever drives everything:** `Dashboard!B5` (service level). It feeds `Z = LEGACY.NORMSINV(...)` → safety stock → reorder point → risk class → priority → every KPI.

## Performance

Open ~35 s, full recalculation ~4–7 s, ~6–8 s after editing the service level. That comes from three choices: a streaming ODS writer (the XML is ~875 MB but memory stays flat), row-aligned cross-sheet references instead of 50,000 VLOOKUPs, and cached formula results so it paints on open.

## Two things worth flagging

- **Volatility is measured on monthly CV.** `sigma_daily = sigma_monthly/√30.42`, so a daily CV is structurally ~5.5× the monthly CV — my first pass flagged 98% of SKUs as "high volatility". Fixed by using `CV_Monthly`.
- **`COUNTBLANK` differs from Excel**: LibreOffice counts *text* as blank, so missing-value and non-numeric detection use `ISBLANK`/`COUNTA` instead. This was caught by a check mismatch, not by inspection.

`README.md` documents the schema, formulas, regeneration steps, and caveats. The pipeline is `make_workbook.py` → `verify.py` → `postprocess.py` (the last two need LibreOffice's bundled Python for UNO).
