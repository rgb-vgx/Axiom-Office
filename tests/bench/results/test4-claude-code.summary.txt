## Deliverable

`MonteCarlo_Risk_Model.xlsx` (3.8 MB, canonical) plus `MonteCarlo_Risk_Model.ods` (native LibreOffice Calc). 10 sheets: **Inputs, Assumptions, Distributions, Simulation, Statistics, Sensitivity, Dashboard, Checks, StressTest, README**.

**Nothing statistical is hardcoded** — all 340,000 cells are live formulas over a real 10,000-path simulation.

### Design decisions worth knowing

**Reproducibility without `RAND()`.** LibreOffice's `RAND()` can't be seeded, so I implemented a Park-Miller LCG (`x(n+1) = 16807·x(n) mod 2147483647`) in plain `MOD()` formulas, with 8 independent streams from one seed cell. The largest intermediate product is ~3.6e13, well under 2^53, so the arithmetic is *exact* in doubles.

**Closed-form financial model.** Instead of per-year columns, the growing annuity is solved analytically: `AF = ((1+g)^n − 1)/g` and `DF = (1−q^n)/(1−q)` with `q = (1+g)/(1+r)`. Keeps 10,000 rows fast and avoids circular references.

### A bug I found and fixed

My first version used `SUMPRODUCT(--(range<=range))` for the checks. Testing showed LibreOffice applies **implicit intersection**, not array evaluation, inside `SUMPRODUCT` — so C02/C05/C12 were **silently returning wrong values and passing**. I replaced every array formula with scalar per-row audit columns (Simulation U/V, Statistics row 20) aggregated by `SUM()`. I also hardened the status cells with `IFERROR(...,"FAIL")` and changed the banner to require 13 explicit PASSes, because a `#N/A` status was previously invisible to the overall check.

Two things to flag: the model is deliberately transparent rather than tax-accurate (no depreciation, tax, working capital or terminal value — add as columns in Simulation), and the squared-correlation sensitivity decomposition on Sensitivity is exact only while drivers stay independent; correlated inputs would need a regression-based measure.
