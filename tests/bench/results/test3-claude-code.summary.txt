## Data
100 projects · 5,000 tasks · 500 resources · 7,635 dependencies · 354 risks. Tasks carry all 11 required fields, plus topological Level, hours and earned value. Dependencies support **FS, SS, FF and SF** with lags.

## The one thing worth knowing about the design
Each task has a topological `Level`, and every active dependency runs strictly **low level → high level**. That makes the network a DAG by construction, so a real forward *and* backward pass (early/late start & finish, total float, critical path) resolves in plain formulas with no circular references and no iteration. `Dependencies!O/P` compute the per-link constraints; `Schedule!J–O` do the passes.

## Two things to be aware of

**The Checks sheet shows 29 FAILs — that is correct, not breakage.** The dataset deliberately seeds ~25 defective records so the checks can be seen catching real problems. The `Classification` column labels every red row (seeded defect / knock-on / genuine portfolio state / live stress delay), and there are explanatory notes below the table and on the `Dependencies` sheet. `CIR-001` (circular dependencies in the active graph) genuinely passes at 0.

**Cycle detection is exact; per-edge attribution is not.** Because valid edges always go low→high level, any edge with `Pred Level ≥ Succ Level` is a back-edge and therefore proves a cycle. But only the edges that *close* a cycle get flagged — in a 3-node cycle, two edges are back-edges and the third still runs forward and reads `OK`. Detection is sound; the per-row label on that third edge is a limitation. This is documented on the `Dependencies` sheet and in the README.

Recalc takes ~20 s on open (recalc-on-load is enabled); the `.ods` already has cached values so it opens instantly.
