# AGENTS.md — src/AxiomOffice.WPS

Rules for the WPS Office Linux JS add-in.

## Language level

- ES5 only: WPS embeds CEF Chrome 87, but the add-in intentionally stays ES5.
  Do not use `let`, `const`, arrow functions, template strings, optional chaining,
  `async`/`await`, or other ES2015+ syntax.
- Use `var`, function expressions, string concatenation, and explicit null checks.
- Never call `alert()`, and never let an exception escape the add-in entry points;
  turn failures into `{ok:false, error}` results.

## Generated code

- The `CATALOG` block in `commands.js` between the BEGIN/END generated markers is
  generated by `scripts/generate_mcp_commands.py` from the Python command registry.
  Do not hand-edit it; change the registry/generator and rerun it.
- `MUTATING` is derived from the generated catalog's `undo` flag rather than kept as
  a separate hand-written list.

## Runtime

- The pane and add-in must work without Node at runtime. Node is only a test runner;
  shipped files use browser APIs available in CEF 87.
- Keep the bridge contract with Core (`poll`, `result`, `/wps/*`) unchanged; the WPS
  channel is part of Core API v1.
- The add-in must never call an LLM directly; all model work goes through Core.

## Tests

- Run `node --test tests/wps/*.mjs` from the repository root for the JS unit tests.
- `make test-wps` also runs the Python install and file checks.
- Live WPS tests are manual and must use a temporary HOME/Xvfb; never touch the
  user's running WPS instances.
